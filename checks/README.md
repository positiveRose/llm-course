# Проверки чекпоинтов

Приёмочные тесты к тем пунктам чекпоинтов, результат которых проверяется кодом. Они проверяют ваш проект, а не код курса.

## Как запускать

Скопируйте каталог в корень своего проекта и запускайте pytest оттуда же, где лежат ваши модули и `data/`:

```bash
cp -r путь/к/курсу/course-v2/checks ./checks
pip install pytest
pytest checks/test_cancel_order.py
```

Проверки обращаются к вашему коду только через `checks/adapter.py`. Если модули у вас называются иначе, чем в курсе, поправьте импорты там, а тесты не трогайте. В уроках 14a, 17 и 18 код пишет агент-кодер: дайте ему нужный тест как приёмку.

## Что проверяется

| Файл | Чекпоинт | Что проверяет | Запуск |
|---|---|---|---|
| `test_cancel_order.py` | 1 (урок 03) | инструмент зарегистрирован в трёх местах; 54010 отменён с возвратом 12 990, 54077 без возврата; 51002, 49880 и 54120 не тронуты; повторная отмена отклонена; `data/orders.json` не изменился | `pytest checks/test_cancel_order.py` |
| `test_history.py` | 1 (урок 04) | в истории нет системного промпта; у каждого `function_call` есть `function_call_output` с тем же `call_id`; `seq` идёт 1, 2, 3 без пропусков и не начинается заново после перезапуска | `pytest checks/test_history.py --db support.db` |
| `test_injection_basics.py` | 3 (урок 14a) | фильтр ответа оставляет ссылку на разрешённый хост и вырезает чужие в markdown, HTML и голом виде, в том числе похожие хосты (`shop.example.evil.com`, `evil.com/shop.example`, `shop-example.com`, `shop.example@evil.com`), текст вокруг сохраняет; инструменты берут клиента из сессии, а не из аргументов; чужой заказ отвечает как несуществующий; сумма возврата не больше цены товара или переплаты при любой сумме в аргументах; законный возврат проходит | заполните четыре функции урока 14a в `adapter.py`, затем `pytest checks/test_injection_basics.py` |
| `test_forget.py` | 4 (урок 11) | в базе не осталось строк с id пользователя и с его строкой-канарейкой; нет сообщений без сессии; чужие сессии на месте | `pytest checks/test_forget.py --db support.db --user U-42 --canary "моя собака Жужа"` |
| `test_idempotent_refund.py` | 5 (урок 18) | тот же вызов дважды, тот же вызов после падения процесса, новый вызов от новой генерации и повторная отправка сообщения дают один возврат; второй товар того же заказа вернуть можно | заполните четыре функции урока 18 в `adapter.py`, затем `pytest checks/test_idempotent_refund.py` |

Проверка чекпоинта 3 не видит первое правило урока 14a, недоверенный текст в результатах инструментов, а не в `instructions`: его смотрят в коде на защите. Проверка чекпоинта 4 смотрит только базу. Логи, кэши и данные у провайдера из вашего списка мест хранения проверяет ваш собственный сценарий удаления.

Зелёный тест значит только одно: ни одно правило из таблицы не нарушено. Отчёт с числами сдаётся отдельно.
